# Boobot Whitepaper

## Vision

An assistant should work the way you do. It should remember what you told it, respect the limits you set, and never trap you with a single model. Boobot is built so that the person, not the vendor, decides how the work gets done.

## Mission

Give every user one assistant with a durable memory and a free choice of engine, and give the community a transparent place to follow what is real and what is still pending.

## Product principles

1. Memory is visible and editable by its owner.
2. The model is a setting, not a contract.
3. Public facts are published only when they are stated, and shown as pending until then.
4. The market view works on its own and never waits for a token.

## Roadmap

### Phase 1: Foundation

Brand, public site, project register and a live market view that does not depend on any launch.

### Phase 2: Workspace

The conversation window with editable memory and per-task model choice.

### Phase 3: Community

Shared assistants, a place for builders to compare setups, and public reporting.

### Phase 4: Ecosystem

Open tooling so other teams can extend what Boobot can do.
